# Threat model

| Threat                                                                                  | Control                                                                                                                                                                                                                                                                               | Test                                                                                                                         |
| --------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------- |
| Internet client submits a fake approval                                                 | Device signature, role, revision compare-and-swap, policy checks                                                                                                                                                                                                                      | `worker/tests/auth.test.ts`, `questions.test.ts`                                                                             |
| Agent downgrades a mandatory approval                                                   | Requirement resolved from trusted policy; caller can only strengthen                                                                                                                                                                                                                  | `packages/protocol` policy tests, client bridge tests                                                                        |
| Proxy satisfies a `human-required` question                                             | Relay refuses proxy actions; clients re-check; model hard-blocks                                                                                                                                                                                                                      | `questions.test.ts`, `packages/decision-model` tests                                                                         |
| Another desktop, or the relay, passes off an answer as the person's on the computer     | Only the `owner-desktop` role may sign `human-desktop` provenance, never a Remote Host; relay and every client check the signer's certified role; committed only when the asking desktop declared `owner-desktop-answers-v1`, so an older desktop never receives one                  | `worker/tests/owner-answers.test.ts`, `packages/client/tests/owner-answers.test.ts`, `app/tests/answer-attribution.test.tsx` |
| Another desktop, or the relay, passes off a follow-up as the person's from the computer | Besides a phone or tablet, only the `owner-desktop` role may sign a human message, never a Remote Host; relay and every client check the signer's certified role; committed only when the asking desktop declared `owner-desktop-messages-v1`, so older asking desktops never get one | `worker/tests/owner-messages.test.ts`, `packages/protocol/tests/thread.test.ts`                                              |
| Local web page or process injects answers                                               | Loopback bind, Host/Origin checks, per-pane bearer                                                                                                                                                                                                                                    | `packages/client` MCP tests                                                                                                  |
| Stolen or forwarded QR                                                                  | Five-minute single-use invite, 6-digit code confirmed on the desktop, pinned owner key                                                                                                                                                                                                | `pairing.test.ts`                                                                                                            |
| Replay of a recorded signed request or answer                                           | Nonce window, timestamp skew, idempotency keys, revision CAS, action-id binding                                                                                                                                                                                                       | `auth.test.ts`, `hardening.test.ts`                                                                                          |
| Race across an `await` (revocation, expiry, rotation, upload, deletion)                 | Re-validate inside the final synchronous transaction; atomic claims                                                                                                                                                                                                                   | `hardening.test.ts`                                                                                                          |
| Wrong pane or session receives an answer                                                | Exact host/pane/generation/principal/incarnation/session/worktree match, else `needs-attention`                                                                                                                                                                                       | client delivery tests                                                                                                        |
| Crash between typing and acknowledging                                                  | Injection intent first; reconcile by marker; never re-type blindly                                                                                                                                                                                                                    | client delivery tests                                                                                                        |
| Relay tampers with ciphertext, metadata or provenance                                   | AEAD with bound AAD; signed records commit to envelope digest; role/provenance verification                                                                                                                                                                                           | crypto and app tests                                                                                                         |
| Relay forges, rolls back or swaps the involvement preference                            | Record signed by a phone, tablet or the owner desktop (never a Host), verified against the pinned owner chain; desktop keeps the highest verified revision and refuses older, swapped or withheld records                                                                             | `worker/tests/involvement.test.ts`, `packages/client/tests/involvement.test.ts`                                              |
| Involvement preference or a consensus weakens an approval                               | Nothing in policy reads it; `enforceRequirement` and `applyAction` are unchanged; a preparation report is the agent's account, never an answer                                                                                                                                        | `packages/client/tests/mcp.test.ts`                                                                                          |
| Compromised push endpoint                                                               | Generic payload, no content, endpoint allowlist against SSRF                                                                                                                                                                                                                          | `push-jobs.test.ts`, `tests-node/webpush.test.ts`                                                                            |
| A phone, a Remote Host or a pane's agent asks for an agent-stopped push                 | Owner-desktop role only (`403` for any other); the body is the protocol version alone (`400` otherwise); a pane's bearer cannot reach it, and a Remote Host's bridge refuses before sending. Which stops count, and whether the person is away, stay with the host app                | `worker/tests/push-jobs.test.ts`, `packages/client/tests/agent-stopped.test.ts`, `packages/client/tests/mcp.test.ts`         |
| An agent-stopped push or its request reveals which agent, pane or project, or why       | The request names nothing and the bridge call takes no arguments; the push is `{"type":"agent-stopped"}` under the strict `PushPayload`, checked before any send; the service worker fixes the lock-screen text, and a stray field neither opens a question nor shows                 | `push-jobs.test.ts`, `packages/client/tests/agent-stopped.test.ts`, `app/tests/sw-core.test.ts`                              |
| An older phone app shows an agent-stopped push as something it is not                   | Sent only to an endpoint that subscribed declaring `agent-stopped-push-v1`; subscribing the same endpoint and keys again without it withdraws it, and earlier endpoints start unable. An app declares only what its active service worker can show; the relay rechecks before sending | `push-jobs.test.ts`, `migrations.test.ts`, `app/tests/push.test.ts`, `app/tests/sw.test.ts`                                  |
| Agent stops flood the phone, or arrive long after they matter                           | One accepted a minute for the whole relay, whoever asks, taken before the send; a request in quiet hours is dropped, never deferred; a fixed topic and a ten-minute TTL leave an offline endpoint at most the latest, none after ten minutes; every outcome is final, never retried   | `push-jobs.test.ts`, `packages/client/tests/agent-stopped.test.ts`                                                           |
| The relay profiles when you are away from your computer                                 | Accepted: each request, dropped or not, tells it an agent on that computer stopped, and when, so they were likely away; never which agent, pane or project, why or how many. Besides request metadata it keeps only when it last accepted one, purged after a day or by a full reset  | `push-jobs.test.ts` (the daily cleanup has no test), `packages/client/tests/agent-stopped.test.ts`                           |
| A push service learns that an agent stopped                                             | Accepted: it sees each send's endpoint, time, size, TTL, urgency and the relay's VAPID key, and the fixed `Topic: agent-stopped` tells it the kind, though the payload, only a type, stays encrypted under RFC 8291. Nothing about which agent, pane or project reaches it            | `push-jobs.test.ts`, `tests-node/webpush.test.ts`                                                                            |
| Malicious Markdown, HTML, SVG or terminal escapes in content                            | Plain-text renderer, no `innerHTML`, no SVG, magic-byte sniffing, sanitized terminal text                                                                                                                                                                                             | app and client tests                                                                                                         |
| Provider API keys leak                                                                  | Worker secrets only; short-lived one-use tickets; scrubbed provider errors                                                                                                                                                                                                            | worker voice tests                                                                                                           |
| Excess voice or upload usage                                                            | Per-device quotas, session limits, monthly budget by audio duration                                                                                                                                                                                                                   | `hardening.test.ts`                                                                                                          |
| Revoked device keeps access                                                             | Immediate lockout, sockets closed, grants withheld, key rotation for new data                                                                                                                                                                                                         | `devices.test.ts`, `hardening.test.ts`                                                                                       |
| Local database copied off the desktop (backup, sync folder, disk image)                 | Question and answer content stored only as ciphertext under the epoch key in the key store; legacy rows sealed on start, then `VACUUM`, WAL truncation and `secure_delete`; plaintext only in the opt-in decision-model history, secrets-filtered                                     | `packages/client` at-rest tests, `packages/decision-model` learner tests                                                     |
| Orphaned storage                                                                        | Reserve/upload/complete state machine, garbage collection, retention jobs                                                                                                                                                                                                             | `attachments.test.ts`                                                                                                        |

Out of scope: a compromised Cloudflare account, a compromised computer or phone, and malicious browser extensions with page access.
